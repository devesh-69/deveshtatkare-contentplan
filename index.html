KEYWORD RESEARCH

Run the same research process before every draft

The plan gives you the topic boundary. Keyword research chooses the exact primary query and supporting terms.

01

Start with seed terms

Expand around the article title, problem language, implementation terms and modifiers.

technical seo, technical seo audit, indexing issues, robots.txt, canonical tags
02

Map search intent

Decide whether the SERP is informational, problem-solving, commercial investigation or service-led.

03

Study SERP structure

Record ranking pages, headings, questions, formats, tools, screenshots and obvious gaps.

04

Choose one primary query

Do not force near-identical keywords into multiple URLs when they share the same intent.

05

Build supporting terms

Add terms that help answer the task naturally. Do not create sections just to insert keywords.

06

Define what not to cover

Write the page boundary before drafting. This is your main anti-duplication control.

LINKING SYSTEM

Internal and external linking rules

Link because the destination genuinely helps the reader. Do not use a forced link quota.

INTERNAL

Link up and sideways

Up: pillar for wider context.

Sideways: 1-3 related cluster posts that solve the next task.

Commercial: Technical SEO service when the reader needs implementation.

EXTERNAL

Prefer first-party documentation

Use Google Search Central, Search Console documentation, Chrome/web.dev and official specifications where relevant.

Use third-party sources when they add original testing or independent research.

DO NOT

Turn every article into a mini pillar

A robots.txt post should not contain full deep dives on sitemaps, canonicals, Core Web Vitals and JS SEO.

Keep detailed explanations on their own URLs and link to them.
